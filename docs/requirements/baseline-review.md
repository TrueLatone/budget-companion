# Requirements baseline review

## Source versions and review scope

The cover, header and Revision History agree on v1.2 and 27 November 2026 for the Vision, Use-Case Specification, and Software Development Plan. The embedded model contains UC01–UC31. The supplied requirements changelog covers Vision and Use-Case revisions, and the dated Software Development Plan separately confirms its revision. Vision §1.1 still cites Development Plan v1.1. Its reference needs correction in the official artifact.

The runtime and test sources on the documentation branch match `main` at `d61475d`. This review records conflicts and gaps for decision. The [public roadmap](../management/README.md) identifies schedule targets and proposed scope.

## Open requirements and implementation questions

| Topic | v1.2 baseline | Current behavior or open decision |
| --- | --- | --- |
| F13 · UC19–UC21 | The model maps Spending History to view, edit and delete. UC19 describes a selected month's date range, newest-first, planned/unexpected totals and normalization of reversed bounds. Keyword and category/type/status filters are proposals. | Vision F13 repeats F11's unexpected-expense wording. Current History normalizes reversed dates but accepts ranges across owned months and orders ascending by expense date and ID. The Dashboard's newest-first recent list is separate. Correct the Vision description and retest History's scope and ordering. |
| F08 · UC10, UC11, UC29 | UC10 confirms, locks and redirects. UC11 requires a separate explicit Create / Verify action and preserves matching tasks on replay. UC29's proposed target flow says confirmation also creates the initial schedule. | UC29 conflicts with UC10/UC11, and the UC11 actor note still implies initiation through confirmation. The live route calls `confirm_and_schedule()` in one transaction. The explicit POST can verify and repair. The current integrated regression expects automatic scheduling. Resolve the release contract before changing any assertion or claiming conformance. |
| F05, F06, N07 · UC05, UC08–UC11, UC27–UC29 | The flow uses integer VND, exact P0, protected P1 minimums and complete conservation. UC28 and UC29 add prior-month reuse and an optional savings target. | New months require 1,000-VND planning units for inputs, allocations and splits. Legacy months retain one-VND planning units, and actual transactions still use integer VND. Clarify permitted units in the requirements. A planned-savings remainder does not satisfy UC29, and recurring flags do not provide UC28 copying. |
| F10, N05 · UC16, UC18 | Repeat-safe key-based submissions and a browser prompt for an additional identical actual purchase. UC18 separates these scenarios. UC16's alternative 5 describes a quiet repeat using form-token wording. Alternative 7 places browser repeats under concurrent conflicting writes. | Matching direct retries preserve one record, and changed payloads with the same key conflict. Browser repeat handling uses the previously saved values and only permits a confirmed second actual-mode purchase. Planned-limit replay cannot create a second purchase. A repeat review and simultaneous conflicting writes are separate scenarios. Clarify the UC16 alternatives and retain separate acceptance checks. UC16 says category comes from the planned expense, while the service can accept an authorized category override. |
| F12 · UC14, F11 · UC18 | Bill dates and editable self-declared payment status, and optional impact scope for unexpected expenses. | The service supports bill payment status and expense impact scope. The Expense page lacks the payment-status control, and the unexpected-purchase create form lacks a scope selector. Expense edit already supports scope. Review the UI and verify it separately. |
| F28–F31 · UC22, UC30 | UC22 includes category transaction detail, a three-month initial trend, per-expense Month/Day progress and daily goals. The daily goal floors the remaining allocation divided by days left, including the selected day, at zero. UC30 compares matching periods and browses six calendar months, leaving unsupported deltas unknown. | The selected-month Dashboard, four-segment donut grouping, priority progress and recent transactions are covered. Category drill-down, trend, Month/Day per-expense progress, persistent Day mode and the detailed compare view are absent on the reviewed source. UC30 leaves comparison completeness and shorter prior-month boundaries unspecified. Reconcile the two-owned-month prerequisite with the missing-prior-month fallback. |
| F16–F20 · UC23–UC26 | Read-only recommendations, explicit readiness, and closed-month reliability independent of readiness. F20 adaptation is planned. | Current tests cover status-only decisions, stale/unsafe conflicts, thresholds, incomplete purchases, and reliable fully resolved months. | F33, F36, F38 · UC04, UC07, UC31 | Profile updates and in-app reminders remain MUST. | F37 · UC06 | Unavailable or unowned periods are denied. The alternative flow lists both an HTTP 404 and return to the authorized list. | The direct selection route returns 404. Clarify whether return to the list is expected as navigation from the error page or as an automatic redirect. |
