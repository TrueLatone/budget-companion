# Expense and check-in testing

Use this workspace to record Build 3 functional execution and supporting regression tests for expense and check-in.

Exercise schedule handoff and planned schedule visibility (UC11–UC12), Expense Plan and due dates (UC13–UC14), planned check-in and recording (UC15–UC16), confirmed zero and unexpected expenses (UC17–UC18), and history, edits and deletion (UC19–UC21). Check the implemented UI and known limitations for the tested build. See the [requirements and traceability](../../../../requirements/README.md), [PA4 component testing scope](../../../../pa4-test-coverage-matrix.md) and [Build 3 verification](../../../../build3-verification.md).

1. Record the run's commit, tester, environment, case IDs and commands in the [execution report](test-execution.md). Enter each observed outcome and evidence reference in [test results](test-results.csv).
2. Capture the applicable period and task state, the recorded result, and any history or totals changed by the case. Save reviewed screenshots in [evidence/](evidence/) and approved pytest XML and logs in [automated/](automated/). Use the [shared naming and relative path conventions](../../../README.md#evidence-and-defects).
3. Write reproducible failures in the [defect log](defects.md) and include an approved public issue reference once available. Reference its key in the results row.
4. When requirements change, record the applicable revision, update the case design in the official test case document, and append a result for the retest. Keep prior outcomes and evidence tied to their original revision and commit.
